# WebUI 可视化配置教程

需要 AstrBot **4.10.4 或更新版本**。在 WebUI → 插件 → 科研最小实验 → 配置中，
通过成员卡片、下拉框、阶段多选、数字输入和权限开关完成配置。日常使用无需编写 JSON。
保存后重新加载插件生效。

## 1. 选择配置来源

| 下拉选项 | 实际使用哪套配置 |
| --- | --- |
| 自动（默认） | 旧版 JSON 非空时继续使用旧配置；没有旧 JSON 时使用表单 |
| 可视化表单 | 使用下面的表单，忽略旧版 JSON，包括旧 JSON 中的执行权限 |
| 旧版 JSON | 仅使用页面底部的旧版实验 JSON |

**第一次安装直接填写表单即可。已有 JSON 用户请先填好表单，再选择“可视化表单”。**
自动模式下，如果旧版 JSON 非空，修改表单不会改变实际实验设置。
两套配置不自动转换、不互相叠加，也不因升级开启付费操作。
旧 JSON 原文保留，方便自行核对和回退。

旧配置中使用多个 SSH 平台、自定义平台名称或其他高级字段时，可继续使用旧版 JSON。
表单提供 `local`、`ssh`、`autodl` 三个固定平台名称，每类一个设置组。
已有任务保存了平台名称与模型设置；切换前应先结束相关任务，
或保留其原配置完成恢复与归档，避免旧任务找不到平台或成员。
保存新配置不改写已有任务的分工、模型或批准记录。

## 2. 设置谁可以使用

只给自己使用且已是 AstrBot **消息管理员**时，留空即可。
仅登录 WebUI 不等于消息账号有管理员权限。
需要开放给其他用户时，添加“允许的消息用户”卡片：

| 输入框 | 填写内容 |
| --- | --- |
| AstrBot 平台 ID | 例如 `my-telegram`，使用 AstrBot 实际配置的平台 ID |
| 该平台上的用户 ID | 例如 `12345`，直接填文本，不用写引号、方括号或 JSON |

同一用户在不同平台的权限分别设置。底部“旧版用户身份列表”的已有授权仍有效；
撤销旧授权时也需删除那里的条目。

## 3. 添加成员并勾选负责阶段

在“参与者与阶段分工”中点击添加，下拉选择 **Codex 成员** 或 **DeepSeek Harness 成员**。
可以添加多位使用相同 harness、不同模型的成员。

| 配置项 | 怎样填写 |
| --- | --- |
| 成员名称 | 唯一名称，例如 `builder`、`reviewer` |
| 模型标识 | 自己明确选择且账号可用的标识；没有默认模型，不会自动替换 |
| 模型提供商 | Codex 通常留空；DeepSeek 可填 ACP 提供商标识，与模型标识自动组合 |
| 职责说明 | 例如“实现代码与汇总”“检索文献与检查实验公平性” |
| 负责阶段 | 多选；五个阶段都必须有人负责，可由同一人承担全部阶段 |
| 发言顺序 | 数值越小越靠前；相同数值按卡片列表顺序 |
| 本机启动程序 | 留空使用 `codex` 或 `dsh`；不在 PATH 中时填绝对路径 |
| 启动参数 | 每个参数单独添加一项；不用写 JSON 或额外引号 |
| 联网搜索方式 | Codex 下拉选择关闭、缓存或实时联网，默认关闭 |

各阶段按成员发言顺序执行。**最终汇总使用勾选了该阶段的成员中排序最靠前的一位。**
刚添加的成员默认勾选全部阶段，请按需要调整。只用一位成员时可保持全部勾选。

常见的两成员分工：

| 成员 | 模板 | 负责阶段 | 顺序 |
| --- | --- | --- | --- |
| builder | Codex | 实验设计讨论、编写实现、最终汇总 | 10 |
| reviewer | DeepSeek Harness | 想法完善与检索、实验设计讨论、公平性检查与分析 | 20 |

Codex 的程序和参数留空时使用 `codex app-server`。也可以填写 `C:/Tools/codex.exe`，
参数留空仍使用 `app-server`。自定义 `model_provider` 时才填写“模型提供商”。
认证由本机 harness 管理，不是 AstrBot 默认聊天提供商。

DeepSeek 的程序和参数留空时使用 `dsh --profile acp`。
**Windows 请明确使用 Node 启动**：

1. 程序填写实际 `node.exe` 路径，例如 `C:/Program Files/nodejs/node.exe`。
2. 参数依次添加三个条目：DSH 的 `lib/bin.js` 绝对路径、`--profile`、`acp`。
3. 不要将整条命令写进一个输入框，也不要使用 `.ps1` 或 `.cmd` 包装脚本。

DeepSeek 模型选择值以本机 ACP 的 `configOptions` 为准。常见二元选择值可分别填写
准确的“模型提供商”和“模型标识”，插件自动编码，无需手写 JSON。
其他形式将提供商留空，在模型框原样粘贴完整 ACP 选择值。
显示名称不一定等于选择值，不能凭名称猜测。
模型已配置、被发现和调用成功是三种状态；`research models TASK_ID` 只查看已有记录。

## 4. 用户 AGENTS.md（可选）

填写已有文件的绝对路径，例如 `C:/research/AGENTS.md`，也可以留空。
表单无需双反斜杠或额外引号。内容由你控制，插件不会创建或改写此文件。
任务目标、方案、分工、指标保存在任务文档里。

## 5. 下拉选择实验平台

下拉切换后显示对应平台的设置组，其他组的设置继续保留。
保存设置不会查询实例、登录 SSH、创建资源或执行实验。

| 选项 | 必填或需核对的内容 |
| --- | --- |
| 本机运行 | 仅讨论时保持“允许本机执行”关闭，实际运行前再开启 |
| 已有 SSH 服务器 | 地址、端口、用户名、专用远端绝对目录、密钥路径或 SSH agent、远端 Python |
| AutoDL 云实例 | CLI 路径、创建或已有模式、实例类型、资源档位或实例 ID、SSH 设置 |

远端不需要 harness。密钥只填写文件路径，不粘贴私钥或密码。
共享组内服务器 `10.8.176.151` 不属于通用实验执行授权，不能配置为实验平台。

AutoDL 自动创建与关机的填写顺序：

1. 平台选 **AutoDL 云实例**。
2. 使用方式选 **按实验方案自动创建，用完自动关机**，类型选 **Pro**。
3. 填写本机 CLI 路径。令牌环境变量只填变量名；使用 CLI 系统凭据时留空。
4. 添加资源档位，逐项填写名称、说明、准确 GPU 规格、预置镜像、CUDA 下限、
   GPU 数量、磁盘容量和可选地域。模型只能从这些档位选择。
5. 填写 AutoDL SSH 用户、密钥路径和专用目录；创建模式自动获取地址与端口。
6. 准备运行时，明确开启查询、创建付费实例、关机和 SSH 实验执行权限。
   允许启动用于继续任务时重新开启原实例。镜像需事先准备依赖和 SSH 公钥。
7. 确认接受新实例主机密钥的方式；默认不开启自动接受新密钥。

所有执行与实例操作权限默认关闭。保存权限后，**批准方案才会创建付费实例**。
新建任务专属实例在结束、失败、暂停、取消或需要用户输入时尝试关机；
继续任务复用原实例。关机不等于释放或删除数据。
已有实例的关机策略可下拉选择保持、归档后关机或总是尝试关机；
该选项不改变自动创建模式的关机约定。
安装、认证与真实验证缺口见 [AutoDL 教程](autodl.md)。

## 6. 资源上限

全部使用数字输入框。首次使用可保留默认值，无需估算 token 预算。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| 同时推进的任务数 | 1 | 插件同时推进的任务数量 |
| 最多 harness 调用轮次 | 30 | 包含检索、讨论、实现、修复与汇总 |
| 设计讨论轮数 | 2 | 多成员交换意见的轮数 |
| 任务活动时间上限 | 3600 秒 | 不是单次实验时长 |
| 单次实验运行上限 | 600 秒 | 实验进程的最长运行时间 |
| 程序修复次数上限 | 5 | 不用于自动调参追求正结果 |
| 网络错误重试上限 | 2 | 不重复提交结果不明的执行或创建 |
| 单次产物归档上限 | 20000000 字节 | 约 20 MB |
| 观测 token 上限 | 0 | 不启用该阈值；非零时也不是服务商侧硬上限 |

## 7. 保存、重新加载并使用

保存配置并重新加载插件，通过已授权的消息账号发送：

```text
research new 比较我的改动与原有基线，先讨论实验方案
research list
research status TASK_ID
research plan TASK_ID
research models TASK_ID
```

按 Bot 要求添加命令前缀，`TASK_ID` 替换为任务编号。
收到澄清问题时用 `research reply TASK_ID 回答内容`。
先查看方案和版本，再用 `research approve TASK_ID 版本号` 批准；
未回复不会被当作批准。保存表单不触发真实模型验证或远端操作。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 改了表单却没生效 | 是否保存并重新加载；自动模式下旧 JSON 是否非空 |
| 找不到成员添加功能 | AstrBot 是否为 4.10.4 或更新版本，是否更新插件并重新打开配置 |
| 不能创建任务 | 是否添加成员、填写明确模型，并让五个阶段都有人负责 |
| 加载提示某阶段没有负责人 | 在成员卡片勾选该阶段后保存 |
| 提示没有使用权限 | 消息发送者管理员身份，或平台 ID 与用户 ID 是否正确 |
| 找不到程序 | 程序路径、PATH、Windows DSH 的 Node 与脚本路径 |
| 模型被发现但调用失败 | 选择值、登录状态与账号权限；发现不代表可调用 |
| 批准后无法执行 | 平台执行权限及 AutoDL 各项独立权限 |
| 自动创建不能选普通容器 | 当前仅 Pro 支持自动创建，普通容器请选择已有实例 |
| 想保留多个自定义平台 | 使用旧版 JSON 兼容方式 |
